# SmartDrag — ручной чек-лист проверки

Дата актуальности: 2026-09-04  
Текущий безопасный baseline: 230 автоматических тестов, Preview self-check 21/21.

Этот документ разделяет то, что уже можно проверять вручную, и экспериментальные G1/G2-проверки Windows. Не запускай
приложение без `--preview`: production native activation намеренно выключена, поэтому обычный запуск ничего не делает.

## 1. Подготовка

Нужны Windows 10/11, .NET 8 SDK, PowerShell и обычный рабочий стол Explorer. Подготовь:

- небольшой рабочий `.jpg`;
- небольшой рабочий `.png`;
- `.txt` или `.pdf` для отрицательной проверки;
- папку с двумя изображениями для multi-selection;
- по возможности повреждённый/нечитаемый файл с расширением `.jpg` или `.png`.

Запускай команды из корня репозитория `SmartDrag`.

## 2. Автоматический baseline перед ручным тестом

```powershell
dotnet build .\SmartDrag.sln -c Debug --no-restore -p:NuGetAudit=false
dotnet test .\SmartDrag.sln -c Debug --no-build --no-restore --verbosity minimal
python .\scripts\validate_repo.py --allow-build-artifacts
python .\scripts\validate_image_corpus.py
dotnet run --project .\src\SmartDrag.App -- --self-check=artifacts/preview-self-check/manual-latest.json
```

Ожидаемый результат: сборка без ошибок/предупреждений, `162 passed`, static validation PASS, corpus PASS, self-check
`21/21` и exit code `0`. Если этот блок красный, визуальные выводы пока не делай.

## 3. Безопасный Preview

Запуск:

```powershell
dotnet run --project .\src\SmartDrag.App -- --preview
```

### Первый экран и настройки

1. Окно открывается без исключения и сразу объясняет сценарий Add → Choose → Get.
2. По умолчанию выбран русский язык и светлая тема.
3. Нажми переключатель языка: весь видимый текст, статусы, picker и ошибки должны перейти на English.
4. Нажми переключатель темы: цвета, drop-surface, карточки, overlay и текст остаются читаемыми.
5. Перезапусти Preview: язык и тема должны сохраниться.
6. Нажми Reset local data и подтверди: язык возвращается на RU, тема на Light, история очищается. Файлы изображений
   при этом не удаляются.

### Ввод файла

Проверь по отдельности:

1. Кнопка Choose и выбор одного JPEG.
2. Перетаскивание одного JPEG/PNG в drop-surface.
3. `Ctrl+V` после копирования одного файла в Explorer.
4. `Ctrl+O` открывает picker.
5. `Ctrl+L` меняет язык.
6. `Esc` сбрасывает текущий preview, а во время операции запускает отмену.

Ожидаемо для JPEG/PNG: появляется имя без приватного полного пути, thumbnail/metadata, floating action panel с
`Compress` и `Remove Metadata`. WebP до отдельного G3-решения не должен отображаться как доступное действие.

### Отрицательные сценарии

Проверь `.txt`, `.pdf`, папку, multi-selection из двух файлов, отсутствующий файл и повреждённый image-файл.

Ожидаемо: overlay/action panel не запускает действие, исходник не меняется, output не создаётся, появляется понятная
локализованная ошибка без полного пути и технического stack trace.

### Реальная обработка и безопасность

Для рабочего JPEG и PNG отдельно выбери `Compress`, затем повтори с `Remove Metadata`.

Проверь:

- статус проходит через очередь/обработку и не показывает выдуманный процент;
- исходный файл не перезаписывается и его размер/время изменения не меняются;
- создаётся новый output в разрешённой папке;
- output существует и открывается стандартным просмотрщиком;
- повторная обработка создаёт безопасное уникальное имя либо корректно сообщает о конфликте;
- при нажатии Cancel или `Esc` операция завершается как cancelled, output не публикуется частично;
- после завершения показывается completion-card, а Dismiss возвращает приложение в состояние готовности.

Если доступны кнопки Copy result path / Open containing folder, проверь их только на созданном output. Полный путь может
появляться в системном действии копирования/Explorer, но не должен попадать в пользовательский текст SmartDrag.

### History и resize

1. Выполни 7 успешных/отменённых операций.
2. Убедись, что видны не более 6 последних записей и порядок — от новых к старым.
3. В карточках истории нет `C:\Users\...`, секретных директорий или других абсолютных путей.
4. Измени размер окна: wide layout должен перейти в compact stacked layout без потери кнопок и текста.
5. Повтори resize туда-обратно: состояние операции и completion не должны исчезать.

## 4. Windows P0/G1 и G2 — экспериментальная ручная матрица

Эти проверки нужны для доказательства Explorer coexistence и pre-overlay qualification. Они не включают production
activation автоматически. Запускай сначала P0, затем строгий G2:

```powershell
.\scripts\run-probe.ps1 -Mode p0
.\scripts\run-probe.ps1 -Mode g2
```

Для каждой строки ниже начинай отдельный drag и фиксируй, появился ли overlay, изменился ли Explorer drop и что записано
в JSONL. В G2 overlay допустим только для ровно одного существующего JPEG/PNG с подтверждённым filesystem path.

Обязательные сценарии:

1. Windows 10 Explorer, один PNG/JPEG.
2. Windows 11 Explorer, один PNG/JPEG.
3. Windows 11 Explorer с несколькими вкладками — drag только из активной вкладки.
4. Два окна Explorer одновременно.
5. Drag изображения с Desktop.
6. Включённые hidden file extensions.
7. Один `.txt`/`.pdf` — в G2 overlay не появляется.
8. Drag папки — overlay не появляется.
9. Multi-selection — overlay не появляется.
10. Изменение selection прямо перед началом drag.
11. Rename/move/delete файла между preflight и Drop.
12. Обычный drop мимо SmartDrag — Explorer работает как раньше.
13. Вход в overlay и выход из него без Drop.
14. Перезапуск Explorer и повтор drag.
15. Mixed-DPI или отрицательные координаты на втором мониторе.

Для обычного Explorer drop ожидается COPY/NONE без MOVE, без кражи фокуса и без блокировки Explorer. Для SmartDrag-drop
ожидаются запись выбранного действия, точное совпадение preflight/drop path и неизменённый исходный файл.

P0 — только технический signal/coexistence probe; его успешный overlay не закрывает G2. Smoke-запуск без реального drag
тоже не является evidence.

## 5. Что прислать после теста

Одним сообщением пришли:

- результат автоматического baseline;
- для каждого Preview-сценария: PASS/FAIL и короткое описание;
- если FAIL — скриншот и точные шаги воспроизведения;
- для P0/G2 — OS build, режим, последний `.jsonl` и `.summary.json` из каталога probe logs;
- отдельно отметь, был ли включён WebP (его отсутствие сейчас является ожидаемым, не дефектом).

Не удаляй логи неудачного сценария до передачи: по ним можно будет исправить проблему без дополнительных уточняющих
вопросов.
