# ADR-034 — Generated-output deletion requires Windows file identity and handle-bound disposition

Status: **ACCEPTED**

## Decision

SmartDrag may offer `DeleteGeneratedOutput` only when the terminal job carries exactly one `GeneratedArtifact` with a strong platform identity and the current runtime has an identity-safe deletion service.

Windows identity scheme v1 is:

```text
windows-file-id-v1
= VolumeSerialNumber + 128-bit FILE_ID_INFO.FileId
```

`PhysicalOutputManager` captures identity twice around final commit:

```text
capture temporary artifact identity
        -> File.Move(... overwrite:false)
        -> capture final path identity
        -> identities equal ? retain strong identity : discard identity
```

A later delete command MUST:

1. open the current output path with `FILE_FLAG_OPEN_REPARSE_POINT`, `FILE_READ_ATTRIBUTES`, and `DELETE` access;
2. read `FILE_ID_INFO` from that handle;
3. compare the current identity with the identity captured at commit;
4. if and only if they match, call `SetFileInformationByHandle(FileDispositionInfo)` on the **same handle**;
5. close the handle.

The implementation must never perform `verify path -> close -> DeleteFile(path)`.

## Why

Historical path ownership is vulnerable to replacement between completion and command execution. File identity detects path replacement, and handle-bound disposition eliminates the second lookup race between verification and deletion.

Capturing identity on both sides of commit also avoids granting delete authority if the temporary/final path was interfered with while the output was being finalized.

## Reparse points

The deletion verifier opens with `FILE_FLAG_OPEN_REPARSE_POINT`. If the path has been replaced with a symbolic link/reparse point, SmartDrag verifies the reparse-point object itself rather than following it to a target. A replacement therefore fails identity comparison instead of risking deletion of the target.

## Failure behavior

Identity capture failure does **not** make a successful non-destructive output fail. It only leaves `GeneratedArtifact.Identity=null`, which suppresses destructive completion commands.

Identity mismatch at deletion time is a safe refusal. SmartDrag leaves the current file untouched.

## Supersedes

This ADR satisfies the future gate required by ADR-031. ADR-031's capability-gating rule remains accepted; only its v0.7 temporary hard-disable of generated-output deletion is superseded.
