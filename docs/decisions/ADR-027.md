# ADR-027 — One drag session authorizes one idempotent ActionRequest

**Status:** Accepted  
**Date:** 2026-08-31

## Decision

For the single-action drag MVP, an accepted `ActionRequest.RequestId` is exactly the originating `DragSessionId`.

`IJobQueue.Enqueue` is idempotent by RequestId:

- equivalent repeated request → return the original `JobId`, do not enqueue again;
- same RequestId with different action/input/output semantics → reject as an integration fault.

`CommittedActionDispatcher` independently applies the same one-shot/idempotency rule before reaching the queue.

## Why

Native/OLE/UI event delivery can be reentrant or accidentally duplicated. A physical user drop must never create two output jobs. A stable idempotency key also makes this behavior explicit to future adapters and coding agents.
