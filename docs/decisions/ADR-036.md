# ADR-036 — One production composition root, native activation remains explicitly blocked by gates

Status: **ACCEPTED**

## Decision

`SmartDrag.App` owns one composition root: `ProductionRuntimeGraph`.

It wires the deterministic runtime only after `StartupSafetyBootstrap.RuntimeMayStart=true`:

```text
clean StartupSafetyLease
  -> Windows generated-artifact identity service
  -> PhysicalOutputManager (same recovery journal)
  -> GuardedImageProcessor
  -> MVP action handlers
  -> ActionRegistry / ActionExecutor
  -> SequentialJobQueue
  -> DragWorkflowOrchestrator
  -> CommittedActionDispatcher
  -> DragInteractionCoordinator
  -> Windows completion platform
  -> CompletionCommandExecutor
  -> CompletionCoordinator
```

The concrete image codec and production overlay remain injected dependencies. Composition does not choose them prematurely.

`ProductionRuntimeGraph` does **not** register WinEvent/OLE hooks. Native activation remains behind `ProductionActivationPolicy.NativeActivationEnabled=false` until G0/G1/G2/G3 are explicitly accepted.

## Why

The repository had correct modules but no single authoritative wiring path. Multiple ad-hoc composition paths would let adapters bypass the recovery journal, guard decorator, commit gate, identity service, or completion capability rules.

A deliberate native-activation kill-switch prevents a future coding agent from making the application appear finished by launching unproven Windows integration.

## Ownership / disposal order

The graph owns the startup safety lease. Shutdown order is:

```text
completion observer detach
  -> JobQueue.DisposeAsync / worker stop
  -> recovery journal + single-instance lease dispose
```

The recovery journal must outlive all jobs that may still reserve/abandon outputs.
