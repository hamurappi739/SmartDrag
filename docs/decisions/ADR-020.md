# ADR-020 — Completion UI is projected from terminal immutable job snapshots

- **Status:** Accepted
- **Date:** 2026-08-31

## Decision

Processing code does not call completion UI directly. `SequentialJobQueue` stores enough immutable terminal data to project a `CompletionModel`:

- input path(s);
- output path(s);
- action id;
- terminal status;
- optional source/output byte metrics;
- error information.

`CompletionProjector` converts only terminal snapshots into completion UI models. Successful jobs expose result-oriented commands; failed/cancelled jobs expose only safe dismissal until retry behavior is separately designed.

## Consequences

- UI remains replaceable and cannot influence processing semantics.
- The viral compression comparison (`source size -> result size`) has a first-class data path.
- Completion can be unit-tested without a renderer or filesystem.
- Deleting a generated output remains an explicit post-completion command and never affects the source.
