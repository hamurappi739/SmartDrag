# ADR-032 — One active drag interaction owns one consumable overlay authorization capability

Status: **ACCEPTED**

## Decision

`DragInteractionCoordinator` owns the single active `PreparedOverlaySession`.

Rules:

1. a newer prepared drag supersedes any stale active session;
2. commit requires the caller's `DragSessionId` to match the active session;
3. the active capability is consumed and cleared before asynchronous hide/dispatch work;
4. a second commit attempt for the same physical drag is rejected even before queue idempotency is consulted;
5. native drag end/cancel clears authorization regardless of overlay hide success.

## Why

The immutable commit gate in v0.6 prevents forged action requests, but an integration coordinator is still required to prevent stale UI state, duplicated callbacks, or a previous drag session from retaining authority.

## Consequence

UI/Win32 adapters do not own authorization lifetime. They forward evidence and identifiers to the coordinator.
