# ADR-037 — Destructive completion authorization is consumable per JobId

Status: **ACCEPTED**

## Decision

`DeleteGeneratedOutput` is a consumable destructive capability. `CompletionCommandExecutor` allows at most one terminal destructive attempt per `JobId` for outcomes that establish a terminal identity fact:

- success;
- identity mismatch;
- file missing;
- unsupported/missing identity.

Concurrent/repeated delivery after such an attempt is rejected without invoking the deletion service again.

A generic native/access failure may be transient and therefore releases the attempt marker for a later retry. Cancellation also releases it.

## Why

Even handle-bound identity verification should not be invoked twice because of double-click, UI reentrancy, or duplicated message delivery. After successful deletion, a later object could appear at the same path; the completion should not retain an indefinitely reusable destructive authority.

The rule is redundant with file identity on purpose: file identity prevents deleting a replacement, while consumable command lifetime reduces the number of destructive opportunities and handles concurrency deterministically.
