# ADR-018 — Production overlay qualification is fail-closed before presentation

- **Status:** Accepted
- **Date:** 2026-08-31

## Context

The canonical master requires the overlay to appear only when the drag is sufficiently confident and the payload is supported. The P0 interop probe originally only knew that Explorer had emitted a drag-start accessibility event; it did not know the actual OLE payload until the cursor entered the SmartDrag drop target.

Showing the production overlay from that signal alone would make folders, multi-selections, and unsupported files flash SmartDrag UI, violating the product invariant.

## Decision

Production SmartDrag is fail-closed at the pre-overlay payload gate:

```text
WinEvent drag start
  -> source eligibility
  -> conservative preflight payload evidence
  -> exactly one supported image candidate
  -> time + movement thresholds
  -> overlay may appear
```

If reliable preflight evidence is unavailable, ambiguous, stale, multiple, missing, directory-based, or unsupported, SmartDrag does not show the production overlay.

False negatives are acceptable during MVP; false-positive overlay presentation is not.

`P0SignalOnly` remains available strictly inside `SmartDrag.Windows.Probe` to prove native drag coexistence. It is explicitly non-production behavior.

## Consequences

- G2 is now a hard gate for the product, not UX polish.
- The implementation may initially support fewer Explorer surfaces if path evidence cannot be obtained safely.
- A future agent must not remove the preflight gate to make demos easier.
