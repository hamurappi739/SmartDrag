# ADR-035 — Every concrete image codec is wrapped by the execution guard

Status: **ACCEPTED**

## Decision

Production image handlers must never invoke a concrete `IImageProcessor` directly.

Composition must wrap the codec with:

```text
IImageInspector
      +
ImageSafetyLimits
      ↓
GuardedImageProcessor
      ↓
concrete codec IImageProcessor
```

Before any full decode/encode, `GuardedImageProcessor` performs content-based inspection and evaluates `MvpImageExecutionGuard`.

The inner codec is not called when the guard rejects:

- unknown/unsupported input format;
- animated/multi-frame input in the first MVP slice;
- invalid dimensions;
- source-size limit;
- maximum-dimension limit;
- decoded-pixel-count limit.

## Why

The v0.6 G3 policy existed as a pure contract, but without a mandatory composition boundary a future implementation could accidentally wire handlers directly to the codec and bypass those limits. This ADR makes the resource/safety gate executable architecture rather than documentation.

## Still unresolved

The actual numeric `ImageSafetyLimits` remain a G3 benchmark decision. This ADR does not invent production values.
