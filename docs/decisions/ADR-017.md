# ADR-017 — Image codec dependency remains gated; SkiaSharp is current first candidate

Status: **Provisional / research decision, not package-referenced**

## Decision

Do not add a production image-codec NuGet dependency before G3 is explicitly passed.

For the next technical evaluation, rank SkiaSharp ahead of ImageSharp 4.x as the first candidate, subject to behavior/packaging benchmarks.

## Evidence as of 2026-08-31

- NuGet lists SkiaSharp 4.151.1 as a stable release (2026-08-05) under the MIT license.
- `SkiaSharp.NativeAssets.Win32` is large, so packaged application size must be measured.
- NuGet lists SixLabors.ImageSharp 4.1.1 as current stable (2026-08-20).
- Six Labors documentation states that starting with ImageSharp 4.0.0, direct dependencies require a valid Six Labors license at build time. Commercial-use terms therefore create an additional build/licensing workflow that must be resolved before adoption.

## Why provisional

License simplicity alone is insufficient. The chosen implementation must also prove:
- JPEG/PNG decode safety and limits;
- WebP encode quality/alpha behavior;
- EXIF orientation handling;
- privacy-metadata stripping without unintended visual change;
- ICC/color-profile behavior;
- cancellation characteristics;
- memory behavior on large images;
- Windows packaging size.

No codec library is allowed to leak into `SmartDrag.Core` contracts.
