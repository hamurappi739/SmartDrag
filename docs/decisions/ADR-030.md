# ADR-030 — Startup recovery is journal-driven only; never scan user directories for partials

Status: **ACCEPTED**

## Decision

Startup recovery may attempt deletion only for paths loaded from the durable SmartDrag recovery journal and only when the recorded path still matches the reservation-bound temporary filename convention.

SmartDrag must never perform startup wildcard searches such as:

```text
C:\Users\...\**\*.smartdrag-*.partial.*
```

or enumerate arbitrary user directories looking for cleanup candidates.

Invalid journal entries are removed/ignored without touching the referenced filesystem path.

Missing journaled partials simply cause the stale record to be cleared.

## Why

Recovery is a deletion-capable subsystem. Its authority should be as narrow as possible. A wildcard/age-based cleanup mechanism can eventually delete a file SmartDrag did not create and also requires invasive directory enumeration.

## Consequences

A corrupt/unavailable journal may leave an orphaned partial; that is preferable to guessing which user files are safe to delete.
